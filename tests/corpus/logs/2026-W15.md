## 2026-W15 周记

这周主题：[[agent-memory-patterns]]。很多本地 agent 在长期记忆上卡住，
问题往往不是模型太弱，而是 retrieval 太差。

### 讨论记录

整理了一组设计观察：

1. LLM 本身 stateless，所有"记忆"都是 retrieval。
2. Retrieval 质量 = agent 智商上限。返回错的 chunk = agent 自信地胡说。
3. 现有方案多是 vector-only RAG，对 CJK 极差，对 exact-keyword 极差。
4. 没人认真做 hybrid + rerank 这套工业界 IR 标配。

### 检索系统的设计要求

个人 vault + agent 场景需要的不只是"又一个语义搜索"，而是把信息检索里
成熟的 hybrid retrieval 结构做成一个本地工具：
- BM25 + vector + graph + title 四路召回（[[RRF]] 融合）
- 可选 cross-encoder 重排（[[attention-mechanism]]）
- CJK 一等公民（jieba tokenizer，见 [[sqlite-fts5-cjk]]）
- 全本地，无 API，CLI-first

### 后续验证点

- cold-start search and daemon search should return the same ranking shape
- line-range retrieval should keep agent context small
- title and alias matches need protection from content-only reranking
- CJK queries need both lexical and semantic recall paths
